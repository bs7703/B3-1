# 트러블슈팅 보고서

## SSH 개인 키 파일 권한 경고

### 1. 증상

Windows PowerShell에서 개인 키 파일을 사용하여 EC2에 SSH 접속을 시도하던 중 다음 경고가 발생하였다.

```text
Warning: Permanently added '3.38.244.69' (ED25519) to the list of known hosts.
@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@
@         WARNING: UNPROTECTED PRIVATE KEY FILE!          @
@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@
```

접속 명령의 형식은 다음과 같다.

```powershell
ssh -i "<개인 키 파일 경로>\my-key.pem" ubuntu@3.38.244.69
```

### 2. 원인 가설

개인 키 파일에 다른 사용자도 접근 가능한 권한이 설정되어 SSH 클라이언트가 해당 파일을 안전하지 않은 것으로 판단했을 가능성이 있다. 개인 키 파일의 접근 권한을 우선 점검할 대상으로 판단하였다.

### 3. 검증

오류 메시지에서 `UNPROTECTED PRIVATE KEY FILE`을 확인하였다. 또한 서버 지문을 받아 known hosts에 등록한 기록이 있으므로 당시 접속은 SSH 서버에 도달한 상태였다. 이를 근거로 이 오류는 로컬 개인 키 파일 권한과 관련된 문제로 분석하였다.

### 4. 조치

SSH 키 파일의 접근 권한 문제를 해결 대상으로 분리하고, Windows 파일 속성의 보안 설정에서 상속 권한과 사용자 읽기 권한을 조정하는 방법으로 대응하였다. 접속에는 기존 키 파일과 `ubuntu` 사용자명을 사용하였다.

같은 EC2 퍼블릭 IP로 SSH 접속을 다시 진행하였고, 이후 기록에서 Ubuntu 셸 진입이 확인되었다. 키 파일의 실제 변경 전후 ACL 목록은 오류 로그와 별개의 자료이며, 본 보고서의 해결 결과는 접속 성공 기록으로 확인하였다.

### 5. 결과

이후 접속 기록에서 Ubuntu 로그인 메시지와 셸 진입이 확인되었다.

```text
Welcome to Ubuntu 26.04 LTS (GNU/Linux 7.0.0-1006-aws x86_64)
ubuntu@ip-10-0-1-242:~$ pwd
/home/ubuntu
```

접속 후 Nginx를 설치하고 다음 결과를 확인하였다.

```text
Active: active (running)
HTTP/1.1 200 OK
Server: nginx/1.28.3 (Ubuntu)
```

외부 브라우저에서도 `http://3.38.244.69`의 Nginx 환영 페이지가 표시되었다. [설치 및 접속 검증 기록](evidence-summary.md)에 성공 결과를 정리하였다.

### 6. 재발 방지

- 개인 키 파일의 소유자와 접근 권한을 최초 접속 전에 확인한다.
- 개인 키 파일은 사용자 개인 보관 위치에서 관리하고 공유하지 않는다.
- 접속 전 키 파일 경로, 사용자명, 퍼블릭 IP를 확인한다.
- SSH 접속 오류 발생 시 네트워크 문제, 인증 문제, 키 파일 권한 문제를 구분하여 점검한다.
- SSH 보안 그룹 규칙은 학습자 공인 IP로 제한한다.


## 외부 접속 장애 점검 순서

다음은 외부 접속 장애를 분류하는 점검 절차이다. 실습 중 모두 수행한 진단 로그가 아니라 증상에 따라 적용하는 점검 순서를 정리한 것이다.

1. **라우팅:** EC2가 속한 서브넷에 연결된 라우팅 테이블에서 `0.0.0.0/0 → igw-0c96bf4bc03058ae2` 경로와 활성 상태를 확인하고 IGW의 VPC 연결을 확인한다.
2. **Security Group:** 해당 EC2에 연결된 그룹에서 HTTP TCP 80의 소스 `0.0.0.0/0`, SSH TCP 22의 학습자 공인 IP/32를 확인한다. 현재 접속자의 IP가 바뀌었는지도 확인한다.
3. **IP:** 현재 EC2 퍼블릭 IPv4와 접속 주소를 대조한다. 실습 주소는 `3.38.244.69`였다. 서버 종료 후 이 주소로 정상 동작을 재검증하지 않는다.
4. **서버:** SSH로 접속하여 `systemctl status nginx --no-pager`, `curl -I http://localhost`, 필요 시 `sudo nginx -t`와 `sudo ss -lntp`로 서비스·설정·80번 리스닝 상태를 확인한다.
5. **추가 분류:** 내부 응답은 성공하지만 외부 접속만 실패하면 네트워크 ACL·로컬 방화벽을 확인한다. `Permission denied` 또는 키 파일 권한 경고는 사용자명·키·로컬 키 권한을 별도로 진단한다.

확보한 결과에서 SSH 키 파일 경고 이후 셸 진입, Nginx 실행, 내부 `200 OK`, 외부 브라우저 표시가 순서대로 확인된다. 내부 응답 시각은 한국 시간 2026-10-13 00:22:53 및 01:30:48이다.
